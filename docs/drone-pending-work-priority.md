### 1.1 当前整体第一优先级：自动物流真正跑通

现有代码已经组成三类 EV 物流端点的“发现需求 → 预约真实库存 → 分配无人机 → 取货 → 运输 → 交付 → 提交/失败恢复”链路，并具备端点心跳目录、策略配置、舰队任务队列、双端预约账本、路线显示和世界存档。当前只剩下游戏内故障矩阵人工验收，因此在验收通过前整体闭环仍保持部分完成状态。

实施批次与验收标准：

1. **端点可配置且数据真实**：物品、流体和 EU 端点分别发布实际资源快照；白名单可在 GUI 搜索、追加、删除和清空；请求量、提供上限、优先级、最低保留和最大库存实时影响策略结果。
2. **物流任务拥有完整载荷**：任务持久化资源类型、资源 ID、请求数量、源端点、目标端点、分配无人机、已取数量和已交付数量；旧任务 NBT 安全迁移。
3. **调度和预约原子化**：任务只能选择同所有者、同维度、在线且资源类型匹配的端点；提交预约时重新读取真实库存并扣除已有预约，禁止两架无人机领取同一份库存。
4. **真实搬运执行**：物品、流体和 EU 均通过端点实际能力与无人机货舱/流体舱/电池转移；取货和交付分 tick 执行并记录进度，不能生成或吞掉资源。
5. **失败完整回滚**：手动取消、超时、无人机丢失、端点离线/拆除、区块卸载、权限变化、最终失败和服务端重启都会释放未提交预约；已经取出的资源保留在无人机并进入恢复/返航流程，绝不凭空删除。
6. **路线和状态可观察**：舰队控制器显示任务阶段、源/目标、资源、预约、分配无人机、进度和失败原因；世界只向所有者显示当前维度、在线任务的源目标连线。
7. **闭环验收**：至少完成物品、流体、EU 各一条成功路线，以及库存不足、目标满、取消、超时、重启和两任务竞争同一库存的人工验收记录。

第一批落地（2026-08-16）：三类端点心跳已经携带真实资源快照。物品按注册 ID 聚合 9 格数量，流体记录流体 ID、mB 与罐容量，EU 记录 `gregtech:eu` 的真实储量与容量；快照随端点世界目录持久化，离线记录不再丢失最后一次库存视图。端点 GUI 新增资源 ID 输入框、前后浏览、添加、删除和清空，服务端校验所有者、字符范围、去重和 64 条上限，空白名单继续表示不限制。

第二批落地（2026-08-16）：`DroneJob` 新增兼容旧构造器的物流货单，持久化资源类型/ID、请求量、源与目标端点、分配无人机、已取/已交付数量及 `DISCOVER → RESERVED → TO_SOURCE → PICKUP → TO_TARGET → DELIVER → RETURNING` 阶段；旧的非物流任务按 `NONE` 安全读取。重启时运行中任务仍走标准退避，但已取数量会保留并从送货阶段恢复，避免把在途货物当作未取库存。

第三批落地（2026-08-16）：预约账本增加源/目标双端点原子预约。一次提交同时应用两端白名单、源端最低保留/提供上限、目标端最大库存/请求上限和两端已有预约，实际锁定量取请求量、可提供量与可接收量三者最小值；释放、租约到期和世界恢复会同时维护两个端点的预约总量。旧单端点预约格式继续兼容。

第七批落地（2026-08-17）：自动供需发现从物品扩展到物品、流体和 EU 三类同所有者/同维度端点，继续统一应用白名单、请求量、提供上限、优先级、最低保留、最大库存和已有预约。流体无人机必须安装流体货舱模块，通过端点真实 `IFluidHandler` 每 tick 最多搬运 1000 mB；EU 无人机必须安装 EU 接口模块，通过端点真实 GregTech 能量容器按机体电压和接口安培数分 tick 搬运。运输 EU 使用独立于飞行电池的持久载荷，飞行耗电不会消耗货单 EU；流体和 EU 载荷均支持实体保存/重载，EU 载荷也会随手动回收物品保存。三类任务共用双端预约、无人机分配、携货重试、阶段进度和实际交付完成判定，不生成或直接删除资源。

第八批落地（2026-08-17）：最终重试耗尽或玩家取消任务时，只有实际存在“已取大于已交付”载荷的任务才保留原无人机绑定并进入 `RETURNING`，预约立即释放但物品、流体和 EU 载荷不回滚、不删除。无人机优先返回当前绑定停机坪，不可用时按人工备用顺序和网络优先级选择可自动回收的同所有者同维度停机坪；返航期间注册状态保持 `LOGISTICS_RETURNING`，不会被新任务重新分配。停机坪成功保存无人机物品后阶段改为 `RECOVERED` 并清除任务绑定；运行途中被人工召回时会先安全取消任务，再完成同一恢复提交。失败/取消返航状态和运输载荷均可跨服务端重启恢复。

第九批落地（2026-08-17）：舰队控制器任务区从固定前三条摘要改为最多 128 条、最新任务优先的分页详情。每条显示任务/资源类型、状态/阶段、资源 ID、已交付/已取/请求量、当前预约量、源/目标端点、分配无人机、重试次数和最后失败原因；非终态任务提供带距离与所有者校验的取消按钮。最终失败或取消但仍在返航的任务继续显示世界源目标线路，便于定位恢复进度。

第十批落地（2026-08-17）：携货任务的重试所有权固定到真实承载无人机。进入退避等待时不再清除承载无人机 ID，无人机保持 `LOGISTICS_RETRY_WAIT`、暂停用户程序和自动拾取，退避结束后只能由同一 UUID、同所有者、同维度且模块仍匹配的在线无人机继续送货；其他任务也会把该无人机视为已占用。无人机死亡掉落、区块重载或服务端重启后，载荷与任务不会被另一架空载无人机错误接管；重新部署同一无人机物品后可继续重试或返航。旧存档若出现已取货但承载无人机 ID 缺失，则明确记录 `CARGO_DRONE_ID_MISSING` 并停止猜测分配，避免幽灵交付或资源复制。

第十一批全面收尾（2026-08-17）：预约策略新增真实物理容量约束。物品端点按 9 格总占用、流体端点按 64000 mB、EU 端点按真实能量容量计算剩余空间；最大库存改为限制端点总库存而非单一资源，流体目标已有不同流体时不再创建或接受不可能完成的预约。携货重试只预约实际未交付余量，不再超额锁定目标空间。物品和流体内容、无人机 EU 取送、所有者绑定及策略配置变化会立即发布端点快照，消除 20 tick 周期内基于旧库存重复派单的窗口；周期心跳仍作为外部 EU 变化和在线状态兜底。

第十二批全面收尾（2026-08-17）：调度排除零电无人机，物品任务排除无空闲货舱槽的候选；EU 接口模块在独立运输 EU 非零时禁止拆除，与流体货舱的载荷锁一致。任务队列增加 2048 条硬上限并在提交时清理最旧的已完成/失败/取消历史到 1792 条，尚未返航的终态任务永不被历史清理。端点普通点击、Shift、Ctrl 支持物品 `1/16/64`、流体 `100/1000/16000 mB`、EU `1/4/64` 个 EV 包三档精确调整。端点状态、舰队无人机状态、物流资源类型、任务状态/阶段及常见失败原因改为结构化客户端本地化；无人机控制面板新增独立运输 EU 显示。

第十三批使用闭环收尾（2026-08-17）：物品、流体和 EU 的真实取货与交付成功时统一触发工具臂动作状态；物品显示机械臂声音和搬运粒子，流体复用带实际流体颜色的传输轨迹与桶声音，EU 显示充能声音和电火花，全部按 4 tick 限频避免持续搬运时刷屏。舰队控制器的 128 条任务同步改为活动任务优先、携货返航任务次优先、其余终态历史最后，同组内再按提交时间倒序，长期运行或返航任务不会被新历史挤出界面。

第十四批并发容量收尾（2026-08-17）：预约账本将源端“待取库存”改为按资源 ID 分别统计，将目标端“待入库存”继续按端点总物理容量统计。混装物品端点为一种物品创建出库任务后，不再错误占用其他物品的可提供量；同一目标的不同资源入库仍共同争用真实格数、罐容量或 EU 容量。方向化计数随预约创建、释放、租约过期和 NBT 恢复同步重建，保留原总预约查询兼容接口。

第十五批回收与损毁收尾（2026-08-17）：玩家潜行直接收回无人机时，先安全取消其运行中物流任务；若已有在途载荷，则在载荷完整写入无人机物品后将返航阶段结案为 `RECOVERED`，避免任务继续运行或永久等待实体。无人机被摧毁时立即以 `DRONE_DESTROYED` 进入标准退避/最终返航流程并释放预约，不再等待五分钟运行超时；物品、流体和独立运输 EU 仍保存在同 UUID 的死亡掉落物中，重新部署后可以继续携货恢复。舰队界面增加该失败原因的中英文说明。

第十六批调度饥饿收尾（2026-08-17）：新增不消耗执行尝试次数的任务延迟状态迁移。所有匹配无人机正忙、尚未部署或承载无人机暂时离线时，任务记录 `NO_AVAILABLE_DRONE` 并等待 40 tick 后重新参与调度，但不再递增失败次数、触发永久失败或反复创建新历史任务；无载荷任务释放分配后等待任意合适无人机，有载荷任务继续固定原承载 UUID。真实执行失败、路径失败、端点变化和交付失败仍使用原有有界退避与最终返航语义。

第十七批端点目录收尾（2026-08-17）：物品、流体和 EU 端点被拆除时立即从世界端点目录注销，运行中任务下一次校验会得到明确的端点不可用失败，不再长期保留幽灵地址。目录每 1200 tick 清理超过 24000 tick 未心跳的崩溃残留记录；临时区块卸载只会先变为离线，不会在短期内误删。达到 2048 条上限并注册新端点时也会先执行同一安全清理，避免旧世界最终无法接纳新端点。

第十八批长任务超时收尾（2026-08-17）：已分配且实体仍加载的物流无人机每 20 tick 刷新任务活动时间，使五分钟超时改为检测“承载实体消失或任务长时间无执行器”，而不是从首次分配开始的绝对总时长。远距离飞行、大容量流体和 EU 连续搬运不会在正常工作中被误判超时；实体卸载、丢失或停止心跳后仍会按原超时、预约释放、重试和携货恢复链路处理。

第十九批空闲无人机分配修复（2026-08-17）：修正专用物流无人机的注册状态与调度条件。未安装用户程序的已部署无人机正常上报 `PROGRAM`，现在会与 `READY`、`COMPLETED`、`ERROR` 一并视为可执行物流的空闲状态，不再因为调度器只接受 `READY` 而永远无法接单；显式 `PAUSED` 的调试无人机仍不会被自动打断。安全固件处于返航、充电、恢复、安全待机或紧急降落时，其安全状态优先于程序状态上报，低电或故障处置中的无人机不会被误判为空闲并分配新任务。

第二十批预约 API 一致性收尾（2026-08-17）：端点感知的单端兼容预约现在会持久化 `providing=true` 的出库方向和资源 ID，出库使用按资源统计的待取量，入库使用按端点总容量统计的待入量；创建、释放及 NBT 恢复都会重建正确的方向化计数。原有无资源 ID 的旧单端预约继续按入库容量安全读取，双端自动物流格式不变。该修复保证第三方扩展调用公开单端入口时不会把源库存预约错误算成目标容量占用。

第二十一批验收可观察性收尾（2026-08-17）：舰队控制器为 `RETRY_WAIT` 任务同步距离下一次调度的剩余 tick，并在现有任务详情第三行显示向上取整的秒级重试倒计时。无可用无人机的 40 tick 延迟、路径/端点失败的指数退避和服务端重启恢复现在都能直接区分“正在等待”与“永久卡死”，倒计时归零后随下一次界面同步消失，不改变任务状态机和重试预算。

第二十二批预约存档防御收尾（2026-08-17）：所有预约资源 ID 在构造和读档时统一去除首尾空白并限制为 128 字符，损坏存档中缺少资源 ID 的双端预约会被拒绝，不再生成空资源方向计数。舰队读档完成后立即对照实际任务 ID 清理孤儿预约，同时走标准释放路径扣回源端、目标端和总预约计数；任务列表被截断或 NBT 局部损坏时不会继续占用端点容量直到租约自然过期。

第二十三批任务历史语义收尾（2026-08-17）：任务失败原因统一移除换行、去除首尾空白并限制为 256 字符，损坏或异常扩展数据不会把超长字符串带入世界存档和舰队同步。任务从等待重新进入 `RUNNING` 时清除上一轮错误，最终 `COMPLETED` 时也清除错误；重试次数仍保留历史尝试数量，因此界面不会再出现“任务已正常运行或完成但仍显示旧错误”的矛盾状态。

当前明确未完成：物品、流体和 EU 成功路线以及库存不足、目标满、取消、超时、重启、无人机损毁和两任务竞争同一库存的游戏内人工验收记录。三类资源已具备自动发现、双端预约、模块匹配分配、真实载荷取送、携货重试、最终失败/取消返航和完整任务状态查看，但在故障矩阵人工验收完成前，整体物流闭环仍保持部分完成，不勾选总项。
