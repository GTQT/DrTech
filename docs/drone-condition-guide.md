# EU 无人机条件系统详细使用手册

本文专门说明可视化编程中的所有“条件”用法，包括条件值从哪里来、如何转换为真假、怎样连接“分支”和“条件循环”，以及动作失败状态的判断方法。

移动、挖掘、放置、伐木、补种、收割、物品/流体物流和其他全部节点的完整说明见 [全部 145 个模块逐项手册](drone-module-manual.md)。

## 1. 条件系统的基本结构

一个完整条件通常由三部分组成：

```text
数据来源（传感器/常量/变量）
        ↓ 数据线
比较或逻辑节点（输出布尔值）
        ↓ 布尔数据线
分支 / 条件循环（决定流程出口）
```

例如“无人机电量低于 20% 时返航”：

```text
EU 电量 ──→ 数字比较.left
数字(20) ─→ 数字比较.right
数字比较.result ─→ 分支.condition

开始 ─→ 分支.in
分支.true ─→ 最近停机坪 ─→ 返航 ─→ 结束
分支.false ─→ 继续任务
```

要点：

- 白色流程线只控制“先做什么、后做什么”。
- 彩色数据线只传递数字、布尔、坐标、区域、过滤器或动作状态。
- 数字、布尔、传感器、比较器通常没有流程端口，它们会在流程节点读取输入时自动求值。
- “分支”和“条件循环”的 `condition` 必须接一个布尔输出，不能直接接数字。
- 数字要先经过“数字比较”才能变成布尔条件。

## 2. 在当前编辑器里怎样设置条件

### 2.1 选择节点

点击节点的主体区域，不要点击端口。选中后右侧属性面板会显示该节点的属性。若右侧显示“未选择节点”，说明没有成功选中节点。

### 2.2 设置数字条件值

例如设置数字节点为 `20`：

1. 选中“数字”节点。
2. 右侧属性显示 `Value`。
3. 在属性输入框输入完整数值 `20`。
4. 点击“应用”。

坐标、百分比、数量、半径等数字属性也使用同样方法。`+/-` 适合微调，输入框适合一次写入完整值。

### 2.3 设置枚举条件

“数字比较”“布尔逻辑”“状态判断”等节点使用枚举属性：

1. 选中节点。
2. 用右侧 `<` / `>` 选择要编辑的属性。
3. 点击“下一个”循环切换可选值。
4. 属性摘要会显示当前值。

### 2.4 连接数据端口

1. 左键点击数据来源节点的输出端口。
2. 再左键点击目标节点的兼容输入端口。
3. 右键任一端口可断开当前连线。

端口必须类型相同或兼容。例如数字只能接数字输入，坐标只能接坐标输入。

## 3. 控制流程的条件节点

### 3.1 分支

用途：根据一个布尔值在两条流程之间二选一。

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `in` | 流程输入 | 程序执行到这里时开始判断。 |
| `condition` | 布尔输入 | 必须接入真假条件。 |
| `true` | 流程输出 | 条件为真时执行。 |
| `false` | 流程输出 | 条件为假时执行。 |

典型连接：

```text
开始.next → 分支.in
数字比较.result → 分支.condition
分支.true → 返航
分支.false → 继续移动
```

注意：`true` 和 `false` 是两条独立流程。需要两条路线最终汇合时，可把它们接到同一个允许多流程输入的循环节点，或者各自走到结束节点。

### 3.2 条件循环

用途：只要条件为真就重复执行循环体，条件变为假后退出。

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `in` | 流程输入 | 首次进入和循环体返回的位置。 |
| `condition` | 布尔输入 | 每一轮进入时重新求值。 |
| `body` | 流程输出 | 条件为真时执行循环体。 |
| `done` | 流程输出 | 条件为假时退出循环。 |

正确结构：

```text
开始 → 条件循环.in
条件循环.body → 一个或多个动作 → 条件循环.in
条件循环.done → 结束
条件节点.result → 条件循环.condition
```

条件会在每轮重新求值，因此适合：

- 目标电量低于指定值时持续充电。
- 货舱未满时持续采集。
- 区域内仍有目标方块时持续工作。

风险：如果循环体不改变条件、也没有等待或持续动作，就可能永久循环。例如固定布尔 `true` 直接接条件循环会永远走 `body`。

### 3.3 等待红石

用途：把“目标是否受到红石供电”作为阻塞条件。

- `target` 可选坐标：接入时检查该坐标；不接时检查无人机当前位置。
- 没有红石时节点保持运行，不走 `failed`。
- 检测到红石后走 `next`。

示例：

```text
开始 → 等待红石 → 移动 → 结束
坐标 → 等待红石.target
```

适用于用拉杆、按钮、红石网络启动无人机任务。

### 3.4 等待所有者

用途：等玩家靠近无人机后再继续。

- `radius` 可选数字输入；未连接时读取属性 `Radius`。
- 允许范围 `1–128`，默认 `16` 格。
- 玩家未进入范围时持续等待，进入后走 `next`。

示例：任务完成后等待主人靠近再丢出货物。

### 3.5 普通等待（时间门）

“等待”不是布尔判断，而是按时间阻塞流程：倒计时结束后才走 `next`。

- `duration` 是可选数字输入，单位为游戏 tick；接入数字后优先使用输入值。
- 未连接 `duration` 时读取属性 `Ticks`，默认 `20` tick，也就是约 1 秒。
- 有效范围为 `1–72000` tick；20 tick 约等于 1 秒，1200 tick 约等于 1 分钟。
- 等待期间节点保持 `RUNNING`，不会反复触发后面的动作。

常见用法是在 `NOT_FOUND` 后等待 20–200 tick 再重试，防止无人机每 tick 扫描作物或库存。

### 3.6 有限循环（计数门）

“有限循环”也不读取真假条件，而是让 `body` 精确执行指定次数，然后从 `done` 退出。

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `in` | 多流程输入 | 首次进入以及每轮循环体返回的位置。 |
| `count` | 可选数字输入 | 循环次数；连接后覆盖属性 `Count`。 |
| `body` | 流程输出 | 尚未达到次数时执行。 |
| `done` | 流程输出 | 次数完成后退出。 |

标准连接：

```text
开始 → 有限循环.in
有限循环.body → 动作 → 有限循环.in
有限循环.done → 结束
数字(10) → 有限循环.count
```

次数会限制在 `0–1000000`。设为 `0` 会直接走 `done`；运行器在退出时清除本轮计数，因此以后再次进入可以重新循环。它适合“执行 10 次”，不适合“直到电量充满”，后者应使用条件循环。

### 3.7 遍历区域坐标（集合门）

“遍历区域坐标”按区域中的每个坐标逐一执行 `body`，区域遍历完后走 `done`。它隐含的退出条件是“区域里已经没有下一个坐标”。

| 端口 | 类型 | 说明 |
| --- | --- | --- |
| `in` | 多流程输入 | 首次进入以及每个坐标处理完后返回。 |
| `area` | 必填区域输入 | 要遍历的区域。 |
| `body` | 流程输出 | 每取得一个坐标时执行。 |
| `coordinate` | 坐标输出 | 当前轮的坐标，只能在 `body` 路线中的节点使用。 |
| `done` | 流程输出 | 所有坐标处理完后退出。 |

示例：逐坐标检查方块，匹配时用“挖掘”节点瞬间破坏：

```text
开始 → 遍历区域坐标.in
区域 → 遍历区域坐标.area
遍历区域坐标.body → 分支.in
遍历区域坐标.coordinate → 方块匹配.target
方块过滤 → 方块匹配.filter
方块匹配.result → 分支.condition
分支.true → 挖掘.in
遍历区域坐标.coordinate → 挖掘.target
挖掘.next → 遍历区域坐标.in
分支.false → 遍历区域坐标.in
遍历区域坐标.done → 结束
```

`coordinate` 在循环体外读取会触发运行错误。区域超过运行限制也会进入 `ERROR`；大区域应拆分成多个小区域。

## 4. 布尔条件节点

### 4.1 布尔

用途：提供固定的 `true` 或 `false`。

- 属性 `Value`：点击“切换”改变真假。
- 输出 `value`：可接分支、条件循环、布尔逻辑或逻辑非。

常用于测试程序结构，不建议把固定 `true` 直接用于没有退出机制的条件循环。

### 4.2 逻辑非

用途：把条件反转。

| 输入 | 输出 |
| --- | --- |
| `true` | `false` |
| `false` | `true` |

示例：“停机坪不可用”条件：

```text
停机坪可用.result → 逻辑非.value
逻辑非.result → 分支.condition
```

### 4.3 布尔逻辑

用途：组合两个布尔条件。

| 运算符 | 结果为真的情况 | 典型用途 |
| --- | --- | --- |
| `AND` | 两个条件都为真 | 电量低并且停机坪可用时返航。 |
| `OR` | 任一条件为真 | 货舱满或电量低时返航。 |
| `XOR` | 两个条件恰好一个为真 | 两个状态不同才执行。较少使用。 |

端口：`left`、`right` 是必填布尔输入，`result` 输出组合结果。

示例“电量低或货舱满”：

```text
EU 电量 → 比较A.left
数字(20) → 比较A.right
比较A(<).result → 布尔逻辑.left

货舱占用率 → 比较B.left
数字(90) → 比较B.right
比较B(>=).result → 布尔逻辑.right

布尔逻辑(OR).result → 分支.condition
```

组合三个以上条件时串联多个布尔逻辑节点：先组合 A 和 B，再把结果与 C 组合。

## 5. 数字比较条件

### 5.1 数字比较

用途：把两个数字比较为布尔结果。

| 运算符 | 含义 | 示例 |
| --- | --- | --- |
| `==` | 相等 | 区域目标方块数量等于 0。 |
| `!=` | 不相等 | 目标 EU 读数不等于 -1。 |
| `<` | 左值小于右值 | 无人机电量低于 20%。 |
| `<=` | 左值小于或等于右值 | 货舱空槽小于等于 1。 |
| `>` | 左值大于右值 | 找到的目标方块数量大于 0。 |
| `>=` | 左值大于或等于右值 | 货舱占用率达到 90%。 |

端口：

- `left`：被检查的实际值，通常接传感器或变量。
- `right`：阈值，通常接“数字”节点。
- `result`：布尔结果，接分支、条件循环或布尔逻辑。

建议把实际值放左边、阈值放右边，这样图更容易阅读。

### 5.2 数字运算参与条件

“数字运算”本身不产生真假，但可以先计算阈值或比例，再交给数字比较。

可选运算：`+`、`-`、`*`、`/`、`%`、`min`、`max`。

示例“目标电量必须比无人机电量低 10 个百分点”：

```text
EU 电量 → 数字运算.left
数字(10) → 数字运算.right
数字运算(-).result → 数字比较.right
目标 EU 百分比 → 数字比较.left
数字比较(<).result → 分支.condition
```

除零或模零会产生运行时错误，不能作为普通假值处理。

## 6. 可作为条件来源的数值传感器

这些节点输出数字，通常接“数字比较”。

### 6.1 无人机自身状态

| 节点 | 输出 | 常见判断 |
| --- | --- | --- |
| **EU 电量** | 无人机当前电量百分比 `0–100` | `< 20` 返航；`>= 90` 恢复任务。 |
| **货舱物品数** | 货舱内符合可选物品过滤器的物品总数 | `>= 64` 后导出货物。 |
| **货舱空槽** | 当前可用货舱空槽数 | `<= 1` 时返航卸货。 |
| **货舱占用率** | 货舱占用百分比 | `>= 90` 时停止拾取。 |

### 6.2 目标机器和世界

| 节点 | 输入 | 输出 | 条件用法 |
| --- | --- | --- | --- |
| **目标 EU** | 必填坐标 | 目标当前 EU；无有效能力为 `-1` | `> 0` 判断可抽取电量；先用 `>= 0` 判断能力存在。 |
| **目标 EU 容量** | 必填坐标 | 目标最大容量；无能力为 `-1` | `> 0` 判断有效 EU 容器。 |
| **目标 EU 百分比** | 必填坐标 | 百分比；无能力为 `-1` | `< 90` 决定是否继续充电。 |
| **库存物品数** | 必填坐标，可选物品过滤 | 指定库存面中匹配物品总数 | `> 0` 后才执行导入。 |
| **红石强度** | 必填坐标 | 目标接收到的红石强度 `0–15` | `>= 8` 作为高电平启动条件。 |
| **输出红石强度** | 必填坐标 | 目标对外输出的红石强度 | `== 15` 判断红石端点是否全开。 |
| **光照等级** | 必填坐标 | `MAX/BLOCK/SKY` 光照等级 | `< 8` 时设置照明或执行夜间任务。 |
| **区域方块计数** | 必填区域，可选方块过滤 | 区域内匹配方块数 | `> 0` 时继续挖掘；`== 0` 时结束。 |
| **区域坐标数** | 必填区域 | 区域实际坐标数量 | `<= 4096` 作为安全条件。 |

### 6.3 `-1` 的特殊意义

目标 EU、容量或百分比返回 `-1` 时，表示目标没有可用的 GT EU 能力，并不表示目标电量为负数。

推荐先判断能力：

```text
目标 EU 百分比 → 数字比较.left
数字(-1) → 数字比较.right
数字比较(!=).result → 分支.condition
```

- `true`：目标具有可读取的 EU 能力。
- `false`：目标坐标错误、没有 EU 容器或没有合适能力面。

## 7. 直接输出布尔值的世界条件

这些节点不需要再经过数字比较，可直接接分支或条件循环。

### 7.1 方块匹配

- 必填 `target`：要检查的坐标。
- 可选 `filter`：方块过滤器；不接过滤器时匹配任意有效方块。
- 输出 `result`：目标方块是否符合规则。

典型用法：只挖指定矿石。

```text
坐标 → 方块匹配.target
方块过滤 → 方块匹配.filter
方块匹配.result → 分支.condition
分支.true → 挖掘
分支.false → 结束/检查下一个坐标
```

方块过滤器可以切换白名单或黑名单。白名单表示“只有规则中的方块为真”，黑名单表示“规则中的方块为假”。空规则当前表示匹配任意方块。

### 7.2 坐标可达

- 必填 `target` 坐标。
- 输出导航系统是否认为该目标可达。

适合在移动前预检：

```text
目标坐标 → 坐标可达.target
坐标可达.result → 分支.condition
分支.true → 移动
分支.false → 备用坐标/返航
```

注意：世界可能在预检后变化，因此“可达”为真不保证移动过程中永远不会受阻；移动节点仍可能失败。

### 7.3 停机坪可用

- 必填 `target` 坐标。
- 检查目标是否是在线、启用、所有者兼容、电压兼容且当前可用的无人机停机坪。
- 输出布尔结果。

典型用法：主停机坪不可用时使用最近后备停机坪。

```text
主停机坪坐标 → 停机坪可用.target
停机坪可用.result → 分支.condition
分支.true → 主停机坪坐标 → 返航
分支.false → 最近停机坪 → 返航
```

### 7.4 区域包含坐标

- 必填 `area` 和 `coordinate`。
- 输出坐标是否属于该区域。

适用于：限制无人机只在许可工作区内行动、验证遍历产生的目标、排除边界外坐标。

## 8. 动作状态条件

### 8.1 动作的 `failed` 流程出口

大多数动作节点有：

- `next`：动作成功。
- `failed`：可恢复的语义失败，例如没找到物品、货舱满、目标无效或权限拒绝。

如果只需要“成功/失败”两条路线，直接连接 `next` 和 `failed` 最简单，不需要状态判断。

### 8.2 上次状态 + 状态判断

需要区分失败原因时使用：

```text
动作.failed → 分支.in
上次状态.value → 状态判断.status
状态判断.result → 分支.condition
```

必须让“上次状态”紧跟在要检查的动作之后使用。任何后续执行节点都会更新上次状态，导致读取到别的节点结果。

### 8.3 状态码含义

| 状态 | 中文含义 | 常见产生场景 | 建议处理 |
| --- | --- | --- | --- |
| `SUCCESS` | 成功 | 动作完成 | 走正常任务。 |
| `NOT_FOUND` | 未找到 | 没有成熟作物、范围内没有掉落物、没有库存/目标 | 等待后重试，或检查下一个目标。 |
| `NO_SPACE` | 无空间 | 无人机货舱满、目标库存满 | 返航/导出货物后重试。 |
| `NO_RESOURCE` | 无资源 | 源库存没有匹配物品、货舱没有可丢弃物品、没有手持匹配物品 | 更换过滤器或补充资源。 |
| `NO_ENERGY` | 无能源（预留） | 状态判断节点可以选择，但当前实体动作不会返回此状态 | 不要把它作为当前低电返航的唯一条件；应使用“EU 电量 + 数字比较”。 |
| `OUT_OF_RANGE` | 超出范围（预留） | 状态判断节点可以选择；当前寻路超出搜索范围会统一进入 `ERROR` | 移动前使用“坐标可达”预检。 |
| `UNLOADED` | 区块未加载 | 目标坐标所在区块未加载 | 不强加载区块；等待玩家/区块加载或选择其他目标。 |
| `DENIED` | 被拒绝 | 领地、事件、FakePlayer 权限拒绝，或互动没有效果 | 跳过目标并记录；不要无限重试。 |
| `UNREACHABLE` | 不可到达（预留） | 状态判断节点可以选择；当前寻路失败会统一进入 `ERROR` | 移动前使用“坐标可达”分流到备用坐标。 |
| `INVALID_TARGET` | 无效目标 | 坐标不是对应机器、没有请求的库存面/EU 能力、红石端点类型错误 | 修正坐标、方向或设备。 |
| `FAILURE` | 通用失败 | 没有更具体分类的可恢复失败 | 读取“上次错误”辅助诊断。 |
| `ERROR` | 运行错误 | 图逻辑异常、数学除零、世界在模拟后突变、不可恢复执行错误 | 程序通常进入错误状态；修正程序后重新启动。 |

`RUNNING` 与 `PAUSED` 是内部持续/暂停状态，不在当前“状态判断”属性的可选失败列表中；程序还没有离开正在执行的节点时，后续流程不会执行。

当前版本实际会由实体动作作为可恢复失败返回的状态是：`NOT_FOUND`、`NO_SPACE`、`NO_RESOURCE`、`UNLOADED`、`DENIED`、`INVALID_TARGET`，以及少数通用 `FAILURE`。`NO_ENERGY`、`OUT_OF_RANGE`、`UNREACHABLE` 已保留在程序格式和状态判断节点中，供后续动作细分失败原因，但不能假定当前动作一定会产生它们。

两个容易混淆的现状：

- 无人机没有足够 EU 支付移动、寻路或交互耗能时，动作会保持 `RUNNING` 等待能源，不会走 `failed`，所以低电返航必须在动作前主动判断“EU 电量”。
- EU 导入时目标电池为空、EU 导出时无人机电池为空，当前都返回 `NO_RESOURCE`；目标或无人机电池已满返回 `NO_SPACE`，电压等级不兼容返回 `DENIED`。

`ERROR` 是终止性错误。运行器记录错误后会直接把程序置为错误状态，不会继续走动作的 `failed` 端口。因此应通过“坐标可达”、目标能力数值是否为 `-1` 等条件提前规避；发生后在无线调试区查看错误文本并修改程序。

### 8.4 上次错误

“上次错误”输出字符串，主要用于无线调试和诊断。当前没有字符串比较节点，因此不能直接把错误文本接入分支；流程判断应优先使用标准状态码。

### 8.5 多种失败原因如何分流

例如导入物品失败后：货舱满则返航，无物品则等待，其他错误结束。

```text
导入物品.failed → 分支A.in
上次状态 → 状态判断(NO_SPACE) → 分支A.condition
分支A.true → 返航
分支A.false → 分支B.in

上次状态 → 状态判断(NO_RESOURCE) → 分支B.condition
分支B.true → 等待 → 重试导入
分支B.false → 结束
```

状态判断节点都应直接读取同一个“上次状态”，中间不要插入会执行的新动作。

## 9. 变量构成的动态条件

### 9.1 读取、赋值和累加变量

| 节点 | 作用 |
| --- | --- |
| **读取变量** | 输出指定变量当前数值；从未设置时为 `0`。 |
| **赋值变量** | 把输入数字写入变量。 |
| **累加变量** | 把输入数字加到变量原值。 |

变量名只允许英文字母、数字和下划线，首字符不能是数字；例如 `harvest_count`。运行状态保存时变量也会保存。

### 9.2 用变量限制重试次数

目标：失败最多重试 3 次。

```text
动作.failed → 累加变量(retry, +1) → 数字比较
读取变量(retry) → 数字比较.left
数字(3) → 数字比较.right
数字比较(<).result → 分支.condition
分支.true → 等待 → 回到动作
分支.false → 返航/结束
```

任务成功后可用“赋值变量”把 `retry` 重新设为 `0`。

## 10. 常用完整条件范例

### 10.1 低电或货舱满时返航

条件 A：`EU 电量 < 20`。

条件 B：`货舱占用率 >= 90`。

使用 `布尔逻辑 OR` 合并 A、B，将结果接到分支。真分支接“最近停机坪 → 返航 → 充电”，假分支接工作流程。

### 10.2 只收割成熟目标，没成熟就等待

收割作物本身会在目标没有成熟作物时返回 `NOT_FOUND`：

```text
收割作物.next → 下一个目标
收割作物.failed → 状态判断链
NOT_FOUND → 等待(20 tick) → 重试
DENIED → 跳过目标
其他 → 结束
```

### 10.3 区域还有矿石就继续

```text
区域 + 方块过滤 → 区域方块计数
区域方块计数.value → 数字比较.left
数字(0) → 数字比较.right
数字比较(>).result → 条件循环.condition

条件循环.body → 区域挖掘/遍历挖掘 → 条件循环.in
条件循环.done → 返航
```

区域挖掘本身会完整处理区域，因此更常见的用法是在多个采矿周期或会重新生成方块的区域中使用该条件。

### 10.4 停机坪存在且无人机电量低才返航

```text
最近停机坪 → 停机坪可用.target
停机坪可用.result → 布尔逻辑.left

EU 电量 → 数字比较(<20)
数字比较.result → 布尔逻辑.right

布尔逻辑(AND).result → 分支.condition
```

真分支接返航；假分支可继续任务或进入安全等待。

### 10.5 红石强度达到 8 才开始工作

```text
控制方块坐标 → 红石强度.target
红石强度.value → 数字比较.left
数字(8) → 数字比较.right
数字比较(>=).result → 分支.condition

分支.true → 工作流程
分支.false → 等待(10 tick) → 回到分支
```

若只关心“是否有红石”，直接使用“等待红石”更简单。

### 10.6 目标机器低于 90% 才导出 EU

先排除 `-1`：

1. `目标 EU 百分比 != -1` 得到“存在 EU 能力”。
2. `目标 EU 百分比 < 90` 得到“需要充电”。
3. 用 `AND` 合并两个结果。
4. 真分支执行“充电至目标百分比”，假分支结束或检查其他机器。

## 11. 条件不工作时的排查顺序

1. 确认分支/条件循环的 `condition` 接的是布尔端口，而不是数字端口。
2. 确认数字比较的 `left` 和 `right` 都已连接。
3. 确认比较符号方向正确，例如“电量低于 20”应是 `实际电量 < 20`。
4. 点击节点主体，检查右侧属性是否已经点“应用”保存。
5. 检查坐标是否为绝对世界坐标、维度是否正确、目标区块是否加载。
6. 对目标 EU 读数先检查是否为 `-1`。
7. 对动作失败优先连接 `failed`，需要细分原因时再用“上次状态”。
8. 确认读取“上次状态”之前没有执行其他动作覆盖它。
9. 条件循环一直不退出时，检查循环体是否真的改变了条件。
10. 查看编程器诊断栏和无线调试轨迹；红框节点通常存在缺失输入或配置问题。
